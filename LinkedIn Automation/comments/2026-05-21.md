## Comment 2 — RAG vs agents
Target: https://www.linkedin.com/feed/update/urn:li:activity:7463044852344074242?utm_source=share&utm_medium=member_desktop&rcm=ACoAAC3YDbEB_yE-WKX_VSN0UeD1W2QTnMcm46k

Your rule of thumb matches what we hit on internal docs: RAG when the answer is "what does our runbook say about X" — one retrieval, one generation, easy to log and diff. Agents earn their tokens when the task chains reads across systems (ticket → repo → deploy status), but debugging gets painful fast when step 3 tool output is stale and the loop confidently builds on it. I'd default to RAG + citations for Q&A and only promote to an agent when the user explicitly needs side effects, not richer prose.
