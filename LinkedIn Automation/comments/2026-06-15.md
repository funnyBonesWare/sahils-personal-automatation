## Comment 1 — PRs built for humans, not agents (Rizel Scarlett)
Target: https://www.linkedin.com/posts/rizel-bobb-semple_pull-requests-were-built-for-humans-not-activity-7465146146391433216-oQh2

Fair point on volume. I've started asking agents to ship context with the diff: the original task, what they actually ran (tests, lint), and what they had to guess. Reviewing 400 lines without that is just pattern matching. On the frontend side the scary misses are implicit rules: what must not re-render, socket message order, what happens when the tab goes hidden. Code compiles fine until staging.

## Comment 2 — Reviewing AI-generated PRs (Thiago Polati)
Target: https://www.linkedin.com/posts/tpolatti_reviewing-ai-generated-pull-requests-requires-activity-7459533422668001281-hg6_

Seen this on refactors. The PR solves the ticket, passes typecheck, then breaks staging because the agent never saw where subscriptions hook in or which props need stable references. My bar moved: plan in comments first, one agent per concern, and I manually hit the unhappy path before merge. Fast plausible code is worse than a slow human PR you actually understand.
