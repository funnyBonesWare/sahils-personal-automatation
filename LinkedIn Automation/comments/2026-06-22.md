The jump from jQuery to React felt huge until I stopped memorizing APIs and asked what problem each layer solves: keeping the DOM in sync with state, where truth lives, what actually triggers a re-render. That maps cleanly when you hop frameworks. One frontend fundamental that's easy to skip: how data gets to the UI. Caching, waterfalls, stale-while-revalidate. I've seen sharp engineers struggle there not because React changed, but because the network layer was never part of their mental model.

Good list. On the frontend side, Kafka often shows up as the thing behind the live dashboard: events land in a topic, something downstream fans out to WebSockets or SSE (server-sent events, one-way streaming over HTTP), and the UI has to merge patches without assuming order. The hard part isn't drawing the chart. It's deciding what an event means for row 847 when three updates arrive out of sequence. Event schema design upstream saves you from rewrite-everything render logic downstream.
