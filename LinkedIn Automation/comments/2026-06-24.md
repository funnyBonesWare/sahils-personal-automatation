The checklist is solid. The leak I see most on frontend teams isn't git. It's error reporting SDKs (tools like Sentry that capture crashes) shipping full request URLs with tokens still in the query string, or someone pasting a stack trace into an AI chat with env vars in the frame. Pre-commit hooks catch repo pushes. They don't catch what left the browser. Worth scrubbing URLs in client-side fetch wrappers and treating "share this error" the same way you'd treat a screenshot.

Target: https://www.linkedin.com/posts/christophernorthfield_theres-a-new-http-method-and-if-you-havent-share-7475237816445177858-K2jd/

This is the exact trap I hit building typeahead against a sensitive catalog. GET puts the prefix in server logs and browser history. POST works but it's not safe to retry and CDNs won't cache it. QUERY (RFC 10008, the new read-only HTTP method with a request body) is the clean fix: idempotent like GET, payload stays out of the URL like POST. Frontend caveat: fetch supports it, but your gateway, CDN, and observability stack have to allow it before you flip the switch in production.
