Solid list. The split I keep teaching juniors: lab tools (Lighthouse, PageSpeed, WebPageTest) tell you what a synthetic run saw. Real User Monitoring, RUM for short, tells you what p75 LCP and INP look like on real devices and networks. Bundlephobia wins are real, but React Profiler is where I still find the second bottleneck after bundle size. I once improved Lighthouse and the UI still felt laggy because one Context re-rendered the whole tree on every socket tick. Run both layers before you call it done.

The recursive block tree is the headline. The TransactionQueue is the engineering. User ops apply optimistically to local state, queue as transactions, persist offline in IndexedDB or SQLite, then saveTransactions on the server with WebSocket push to other clients. Same mutation pattern as a todo app, just nested. The part that gets expensive fast is what Ali hinted at: permissions resolved per block node, not per page. Every new feature inherits that constraint.
