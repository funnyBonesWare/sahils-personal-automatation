I keep relearning the same lesson on real-time admin UIs with high-cardinality data: virtualized grids scale until you put React inside the cell.

1️⃣ 𝗪𝗵𝗮𝘁 𝗿𝗼𝘄 𝘃𝗶𝗿𝘁𝘂𝗮𝗹𝗶𝘇𝗮𝘁𝗶𝗼𝗻 𝗮𝗰𝘁𝘂𝗮𝗹𝗹𝘆 𝗱𝗼𝗲𝘀 — AG Grid renders only the visible rows + a small buffer. At any scroll position you have ~30–50 DOM nodes, not a million. That's the entire reason it scales. Break that math and you break the grid.

2️⃣ 𝗪𝗵𝘆 𝗰𝘂𝘀𝘁𝗼𝗺 𝗿𝗲𝗻𝗱𝗲𝗿𝗲𝗿𝘀 𝗳𝗶𝗴𝗵𝘁 𝘆𝗼𝘂 — Every renderer runs in the commit phase × visible rows × every scroll tick. A React.memo'd cell with a stable valueGetter costs ~nothing. A renderer that opens a popover, reads from context, or formats with Intl.DateTimeFormat on every paint costs a few ms × 40 rows × continuously. Suddenly the grid stutters and you blame "AG Grid performance" — it's not the grid. It's the React you bolted onto the grid.

3️⃣ 𝗧𝗵𝗲 𝗲𝘀𝗰𝗮𝗽𝗲 𝗵𝗮𝘁𝗰𝗵𝗲𝘀 (𝘂𝘀𝗲 𝘀𝗽𝗮𝗿𝗶𝗻𝗴𝗹𝘆) — suppressColumnVirtualisation and a bigger row buffer mask the symptom; they don't fix it. The real fix is one of: pull expensive work out of the renderer (precompute on setRowData), debounce popover state into a parent, or replace the renderer with a valueFormatter for cells that don't actually need React.
