𝗢𝗽𝗲𝗻𝗶𝗻𝗴 𝗮 𝗳𝗶𝗹𝘁𝗲𝗿 𝗱𝗿𝗮𝘄𝗲𝗿 𝘀𝗵𝗼𝘂𝗹𝗱𝗻'𝘁 𝗹𝗲𝗮𝘃𝗲 𝗸𝗲𝘆𝗯𝗼𝗮𝗿𝗱 𝘂𝘀𝗲𝗿𝘀 𝗳𝗼𝗰𝘂𝘀𝗲𝗱 𝗼𝗻 𝗮 𝗿𝗼𝘄 𝘁𝗵𝗲𝘆 𝗰𝗮𝗻'𝘁 𝘀𝗲𝗲.

I used to treat accessibility on admin dashboards as "add aria-labels and ship." Then I watched someone Tab through a virtualized table, open a filter panel, and keep typing into a cell that was now covered by the overlay. No error. No crash. Just a UI that felt broken if you weren't using a mouse.

The grid wasn't the problem. Focus never moved with the UI.

1️⃣ 𝗪𝗵𝗮𝘁 𝗴𝗼𝗼𝗱 𝗹𝗼𝗼𝗸𝘀 𝗹𝗶𝗸𝗲 — When a modal or drawer opens, move focus to the first meaningful control inside it (search field, first checkbox), set aria-modal="true" on the dialog surface, and trap Tab within the overlay until it closes. On close, return focus to the element that opened it — usually the filter button — so the user lands where they started instead of at document.body.

2️⃣ 𝗪𝗵𝗲𝗿𝗲 𝘃𝗶𝗿𝘁𝘂𝗮𝗹𝗶𝘇𝗲𝗱 𝘁𝗮𝗯𝗹𝗲𝘀 𝗰𝗼𝗺𝗽𝗹𝗶𝗰𝗮𝘁𝗲 𝘁𝗵𝗶𝗻𝗴𝘀 — AG Grid and similar libraries recycle DOM nodes. A focused cell can unmount on scroll while focus is still logically "there," which produces odd Tab order or silent focus loss. I avoid auto-focusing cells on every row highlight, and I don't open a drawer from a cell click without an explicit button — the opener should be a stable, focusable control you can return to. If the library exposes suppressCellFocus or similar, use it on dense operator views where keyboard users live in the chrome, not the grid body.

3️⃣ 𝗗𝗼𝗻'𝘁 𝗳𝗶𝗴𝗵𝘁 𝘁𝗵𝗲 𝗯𝗿𝗼𝘄𝘀𝗲𝗿 𝗮𝗹𝗼𝗻𝗲 — Radix, React Aria, and MUI Dialog handle trap + restore if you wire the trigger ref through. Rolling your own div with position:fixed often forgets Escape, scroll lock, and restoreFocus — three bugs in one PR. The senior habit: use a battle-tested dialog primitive for filter UX, then spend your time on filter state — not reinventing focus rings.

Perf and a11y aren't separate tickets on data-heavy UIs. A filter drawer that traps focus correctly is also a filter drawer that feels intentional on a warehouse tablet.

Do you return focus to the trigger on close, or let the browser pick wherever Tab lands next?
