𝗔𝗜 𝗰𝗼𝗱𝗶𝗻𝗴 𝗾𝘂𝗮𝗹𝗶𝘁𝘆 𝗶𝘀 𝗺𝗼𝘀𝘁𝗹𝘆 𝗮 𝗰𝗼𝗻𝘁𝗲𝘅𝘁 𝗽𝗿𝗼𝗯𝗹𝗲𝗺, 𝗻𝗼𝘁 𝗮 𝗽𝗿𝗼𝗺𝗽𝘁 𝗽𝗿𝗼𝗯𝗹𝗲𝗺.

I spent months treating Copilot like a faster Stack Overflow — paste a error, accept the suggestion, move on. Then I asked it to refactor a hook that touched WebSocket batching, grid state, and a chart side effect in one file. The diff looked plausible. Staging broke in a way no test caught: stale closures in the socket callback, because the model never saw where subscriptions actually lived.

The model didn't fail. I fed it a mess and expected architecture.

1️⃣ 𝗪𝗵𝗮𝘁 𝗔𝗜 𝗮𝗰𝘁𝘂𝗮𝗹𝗹𝘆 𝗱𝗼𝗲𝘀 — Autocomplete models predict the next token from whatever's in the window right now. They're not retrieving a stored answer and they're not running your app. Missing types, split logic across 400-line files, or no interface definition and you'll get confident code that compiles against the wrong mental model. Clever wording in the chat box doesn't fix thin context.

2️⃣ 𝗛𝗼𝘄 𝗜 𝘄𝗼𝗿𝗸 𝘄𝗶𝘁𝗵 𝗶𝘁 𝗻𝗼𝘄 — Small files. Types and function signatures up top. One concern per ask — "wire this patch merge" not "fix the whole dashboard." Point the tool at the hook, the consumer, and the type file, not just the symptom line. For refactors I ask for a plan in comments first, then one slice at a time. Temperature near zero when I want deterministic glue code; I'll explore options myself when the design isn't settled.

3️⃣ 𝗧𝗵𝗲 𝗻𝗼𝗻-𝗻𝗲𝗴𝗼𝘁𝗶𝗮𝗯𝗹𝗲 𝗽𝗮𝗿𝘁 — Read every line like a junior's PR. Run it. Break the happy path on purpose. AI is strong at boilerplate, tests scaffolds, and explaining APIs I've half-forgotten. It's weak at implicit invariants — what mustn't re-render, what order messages arrive in, what happens when the tab goes hidden. Those still belong to the engineer who's shipped production UIs.

The senior habit isn't "never use AI." It's never skipping the review you'd demand from a teammate.
