𝗦𝗲𝗿𝘃𝗲𝗿 𝗖𝗼𝗺𝗽𝗼𝗻𝗲𝗻𝘁𝘀 𝗮𝗿𝗲 𝘄𝗶𝗻𝗻𝗶𝗻𝗴 𝗮𝗱𝗼𝗽𝘁𝗶𝗼𝗻 𝗮𝗻𝗱 𝗹𝗼𝘀𝗶𝗻𝗴 𝗱𝗲𝘃𝗲𝗹𝗼𝗽𝗲𝗿𝘀.

The latest State of React numbers are funny in a sad way. Around 45% of new projects use React Server Components now. But close to two thirds of those developers report negative sentiment. So the thing everyone is adopting is also the thing everyone is quietly fighting.

I felt the same when I first moved a project to the App Router. The tech wasn't broken. My mental model was. I kept writing React the old way and wondering why it pushed back.

1️⃣ 𝗪𝗵𝗲𝗿𝗲 𝗽𝗲𝗼𝗽𝗹𝗲 𝗴𝗲𝘁 𝘀𝘁𝘂𝗰𝗸

The number one pain is Context. Old habit: wrap the whole app in a provider at the top. But Context only works inside client components. So you reach for use client way too high in the tree, and suddenly half your "server" app is shipping as JavaScript again. Same with useEffect for data fetching. It just doesn't fit a server-first world anymore.

2️⃣ 𝗧𝗵𝗲 𝘀𝗵𝗶𝗳𝘁 𝘁𝗵𝗮𝘁 𝗺𝗮𝗸𝗲𝘀 𝗶𝘁 𝗰𝗹𝗶𝗰𝗸

Push use client down to the leaves. Buttons, inputs, modals. Fetch data right inside the server component and await it. Replace API routes with Server Actions for mutations, and validate every action input with something like Zod, because an action is a public endpoint. Once I stopped fighting the boundary, the boilerplate I used to write just disappeared.

3️⃣ 𝗪𝗵𝗲𝗻 𝗥𝗦𝗖 𝗴𝗶𝘃𝗲𝘀 𝘆𝗼𝘂 𝗹𝗲𝘀𝘀

Honest part. If your app is mostly read heavy, product pages, content, marketing, the wins are big. Smaller bundles, faster first paint. If it's a heavy interactive dashboard with live data everywhere, the gains are modest and the friction is real. Server Components are a tool, not a religion. Pick by the shape of your app, not the hype on the timeline.

Most of the RSC pain isn't the library. It's us porting old habits into a new model.

If you tried Server Components, did the mental model click, or did you bounce back to a normal SPA?
