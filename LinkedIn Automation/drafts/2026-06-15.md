𝗔𝗴𝗲𝗻𝘁𝘀 𝗰𝗮𝗻 𝗼𝗽𝗲𝗻 𝗮 𝗣𝗥 𝗳𝗮𝘀𝘁𝗲𝗿 𝘁𝗵𝗮𝗻 𝘆𝗼𝘂 𝗰𝗮𝗻 𝗿𝗲𝗮𝗱 𝗶𝘁. 𝗧𝗵𝗮𝘁'𝘀 𝘁𝗵𝗲 𝗻𝗲𝘄 𝗯𝗼𝘁𝘁𝗹𝗲𝗻𝗲𝗰𝗸.

Cursor now reports about 35% of their own merged PRs come from autonomous cloud agents. Not tab completion. Full diffs, tests run, merge-ready. I felt the shift on a refactor last month: six files changed while I was in a meeting. The code looked clean. Staging broke on a subtle subscription bug the agent never saw.

Writing got cheap. Review didn't.

1️⃣ 𝗪𝗵𝘆 𝗻𝗼𝗿𝗺𝗮𝗹 𝗣𝗥 𝗿𝗲𝘃𝗶𝗲𝘄 𝗯𝗿𝗲𝗮𝗸𝘀

Human PRs carry intent in the description, Slack thread, or a quick "why I did this." Agent PRs often ship as a clean diff with no story. You skim green lines, hit approve, and miss the part where plausible code solves the ticket but violates a system rule. Lint passes. Types pass. The wrong abstraction still lands.

2️⃣ 𝗪𝗵𝗮𝘁 𝗜 𝗮𝘀𝗸 𝗳𝗼𝗿 𝗯𝗲𝗳𝗼𝗿𝗲 𝗜 𝗿𝗲𝘃𝗶𝗲𝘄

The original task in plain words. Which files were in scope and which were touched by accident. What ran (tests, build) and what was guessed. On frontend work I also want edge cases called out: rerender boundaries, socket message order, tab visibility. Without that package, I'm not reviewing. I'm gambling.

3️⃣ 𝗪𝗵𝗮𝘁 𝗵𝘂𝗺𝗮𝗻𝘀 𝘀𝘁𝗶𝗹𝗹 𝗼𝘄𝗻

Syntax and style can go to linters and a review agent. Humans should judge intent, blast radius, and reversibility. Does this change belong in this layer? Can you roll it back in one revert? One unhappy-path manual test beats reading 400 lines of generated glue. My bar didn't drop. It moved from typing to gatekeeping.

Autonomous agents don't remove the need for review. They make shallow review dangerous.
