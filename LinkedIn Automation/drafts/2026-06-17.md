𝗧𝗵𝗲 𝗪𝗲𝗯𝗦𝗼𝗰𝗸𝗲𝘁 𝗔𝗣𝗜 𝗶𝘀 𝟱 𝗹𝗶𝗻𝗲𝘀. 𝗧𝗵𝗲 𝗱𝗮𝘀𝗵𝗯𝗼𝗮𝗿𝗱 𝗮𝗿𝗼𝘂𝗻𝗱 𝗶𝘁 𝗶𝘀 𝗻𝗼𝘁.

I've shipped real-time admin views where localhost felt flawless and staging on spotty 4G melted the tab. The bug was never the socket handshake. It was piping every message straight into React state with no layers in between.

Starting this Wednesday I'm publishing a weekly frontend system design breakdown. First topic: how to design a real-time dashboard client that stays responsive when ticks arrive 50 times a second.

1️⃣ 𝗗𝗼𝗻'𝘁 𝗹𝗲𝘁 𝗰𝗼𝗺𝗽𝗼𝗻𝗲𝗻𝘁𝘀 𝗼𝘄𝗻 𝘁𝗵𝗲 𝘀𝗼𝗰𝗸𝗲𝘁

One connection manager handles auth, heartbeat, backoff, and resubscribe after reconnect. UI widgets never see raw frames. They read stable state from scoped stores.

2️⃣ 𝗕𝗮𝘁𝗰𝗵 𝗯𝗲𝗳𝗼𝗿𝗲 𝘆𝗼𝘂 𝗿𝗲𝗻𝗱𝗲𝗿

Append ticks to a ref buffer. Flush on requestAnimationFrame or ~100ms. Merge once. Then notify subscribers. Users can't perceive sub-200ms KPI updates anyway. Rendering every message is a stress test, not a feature.

3️⃣ 𝗠𝗲𝗿𝗴𝗲 𝗿𝘂𝗹𝗲𝘀 𝗮𝗿𝗲 𝘁𝗵𝗲 𝗿𝗲𝗮𝗹 𝗰𝗼𝗻𝘁𝗿𝗮𝗰𝘁

Row patch vs delete vs full snapshot. Sequence numbers for out-of-order delivery on reconnect. Document this before you write JSX. Most "wrong number on screen" bugs live here, not in the chart library.
