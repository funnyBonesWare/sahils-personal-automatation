𝗬𝗼𝘂𝗿 𝘀𝗲𝗮𝗿𝗰𝗵 𝗯𝗮𝗿 𝘄𝗼𝗿𝗸𝘀 𝗽𝗲𝗿𝗳𝗲𝗰𝘁𝗹𝘆 𝗶𝗻 𝗱𝗲𝘃. 𝗧𝗵𝗲𝗻 𝗶𝘁 𝗹𝗶𝗲𝘀 𝗶𝗻 𝘀𝘁𝗮𝗴𝗶𝗻𝗴.

I built a global typeahead on a side Next.js app last month. Debounced input, fetch on change, suggestions in a dropdown. Felt done. Then I typed fast on throttled 3G and watched results from two keystrokes ago overwrite the current query. Backspace made it worse. Keyboard nav worked until it didn't. VoiceOver had nothing useful to announce.

The bug was never the API. It was missing layers between the input and the network.

Week 2 of my weekly frontend system design series: how to design a typeahead that stays correct when latency, race conditions, and accessibility all show up at once.

1️⃣ 𝗗𝗲𝗯𝗼𝘂𝗻𝗰𝗲 𝗶𝘀 𝗻𝗼𝘁 𝗲𝗻𝗼𝘂𝗴𝗵

250ms debounce cuts request volume. It does not stop a slow response for "re" from landing after "react" already resolved. You need AbortController plus a monotonic requestId. Only the latest intent wins.

2️⃣ 𝗧𝗵𝗲 𝗶𝗻𝗽𝘂𝘁 𝗶𝘀 𝗮 𝗰𝗼𝗺𝗯𝗼𝗯𝗼𝘅, 𝗻𝗼𝘁 𝗮 𝘁𝗲𝘅𝘁 𝗯𝗼𝘅

WAI-ARIA combobox pattern: focus stays in the input, active option moves via aria-activedescendant, popup is a listbox. Skip this and you ship a demo that fails keyboard and screen reader users on day one.

3️⃣ 𝗖𝗮𝗰𝗵𝗲 𝘁𝗵𝗲 𝗽𝗿𝗲𝗳𝗶𝘅, 𝗽𝗿𝗲𝗳𝗲𝘁𝗰𝗵 𝗼𝗻 𝗳𝗼𝗰𝘂𝘀

Small LRU cache keyed by normalized prefix makes backspace instant. One cheap fetch on focus (trending/recent) saves the awkward pause on first keystroke. Still run the requestId check so cache never overrides a newer query.
