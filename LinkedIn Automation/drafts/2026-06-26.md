𝗡𝗲𝘅𝘁.𝗷𝘀 𝟭𝟲 𝗺𝗮𝗱𝗲 𝘁𝗵𝗲 𝗥𝗲𝗮𝗰𝘁 𝗖𝗼𝗺𝗽𝗶𝗹𝗲𝗿 𝘀𝘁𝗮𝗯𝗹𝗲. 𝗜𝘁 𝗱𝗶𝗱 𝗻𝗼𝘁 𝗺𝗮𝗸𝗲 𝘂𝘀𝗲𝗠𝗲𝗺𝗼 𝗼𝗯𝘀𝗼𝗹𝗲𝘁𝗲.

I flipped reactCompiler: true on a side Next.js dashboard I've been tuning for months. Dozens of hand-placed useMemo and useCallback hooks. Profiler looked better on most routes. Felt like a win. Then I deleted memos around an AG Grid wrapper and scroll stutter came back. Same data. Same row count. Different reference identity on column defs the grid compares by reference.

The compiler fixed most of my React tree. It did not fix libraries that live outside React's reconciler.

1️⃣ 𝗪𝗵𝗮𝘁 𝘀𝘁𝗮𝗯𝗹𝗲 𝗮𝗰𝘁𝘂𝗮𝗹𝗹𝘆 𝗺𝗲𝗮𝗻𝘀

React Compiler v1 analyzes components at build time and inserts the memoization you'd have written by hand. Next.js 16 ships first-class support with a SWC pass so it only touches relevant files. Stable means production-ready, not on-by-default. Most teams still opt in via next.config. Annotation mode ("use memo" per file) is the sane path on brownfield codebases.

2️⃣ 𝗪𝗵𝗮𝘁 𝘁𝗼 𝗱𝗲𝗹𝗲𝘁𝗲 𝘃𝘀 𝗸𝗲𝗲𝗽

Safe to remove: useMemo wrapping pure derivations with no external deps. useCallback on handlers passed to plain DOM or well-behaved children. React.memo on leaf components the compiler already stabilizes upstream. Keep manual memo when a third-party lib checks reference equality (grids, charts, map layers). Keep it when you need exact useEffect dependency control. Keep it for expensive synchronous work you want an explicit performance boundary on. Add a one-line comment on survivors so the next reader knows why.

3️⃣ 𝗧𝗵𝗲 𝗺𝗶𝗴𝗿𝗮𝘁𝗶𝗼𝗻 𝗜'𝗺 𝗿𝘂𝗻𝗻𝗶𝗻𝗴

Enable eslint-plugin-react-compiler alongside react-hooks. Turn on annotation mode in hot files first, not globally on day one. Profile before and after on one real page, not a hello-world component. Bulk-deleting every useMemo is the new "add useMemo everywhere" anti-pattern. Different costume, same regret.

Junior React in 2026 might never hand-write memo. Senior React is knowing exactly which three hooks survive the audit and why.
