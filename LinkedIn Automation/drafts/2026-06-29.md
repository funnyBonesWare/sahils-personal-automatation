𝗬𝗼𝘂𝗿 𝗔𝗜 𝗮𝗴𝗲𝗻𝘁 𝗱𝗲𝗺𝗼 𝗿𝘂𝗻𝘀 𝘁𝗼𝗼𝗹𝘀 𝗶𝗻𝘀𝘁𝗮𝗻𝘁𝗹𝘆. 𝗣𝗿𝗼𝗱𝘂𝗰𝘁𝗶𝗼𝗻 𝗻𝗲𝗲𝗱𝘀 𝗮 𝗵𝘂𝗺𝗮𝗻 𝗰𝗹𝗶𝗰𝗸 𝗳𝗶𝗿𝘀𝘁.

I wired a support sidebar on a side Next.js app with AI SDK 7 and three tools: search docs, draft a reply, send an email. Tokens streamed. Felt magical. Then I pointed it at a real sandbox inbox. The model queued "send" twice on one user prompt. No malice. Just confidence. That's when I stopped treating tool execution as free.

SDK 7 ships first-class approval gates. Not a TODO comment above execute.

1️⃣ 𝘁𝗼𝗼𝗹𝗔𝗽𝗽𝗿𝗼𝘃𝗮𝗹 𝘃𝘀 𝗻𝗲𝗲𝗱𝘀𝗔𝗽𝗽𝗿𝗼𝘃𝗮𝗹

For streamText, generateText, and ToolLoopAgent, set toolApproval on the agent. The loop pauses, you render approve or deny in the UI, then resume with tool-approval-response messages in the history. For WorkflowAgent from @ai-sdk/workflow, put needsApproval: true on the tool definition. The workflow suspends as a durable step. A user can approve hours later and the agent picks up where it stopped. Same human-in-the-loop idea, different runtime. Mixing the two APIs is a common footgun when you upgrade from SDK 5 tutorials.

2️⃣ 𝗪𝗵𝗲𝗻 𝘁𝗼 𝗮𝘂𝘁𝗼-𝗿𝘂𝗻 𝘃𝘀 𝘄𝗵𝗲𝗻 𝘁𝗼 𝗮𝘀𝗸

Read-only lookups can run on auto. Anything that sends email, charges money, deletes rows, or hits an external API with side effects gets approval. needsApproval can be an async function so a large refund needs a click but a small one does not. Policy-as-code beats a blanket "approve everything" button users learn to mash through in two days.

3️⃣ 𝗧𝗵𝗲 𝗮𝗽𝗽𝗿𝗼𝘃𝗲 𝗨𝗜 𝗶𝘀 𝗽𝗿𝗼𝗱𝘂𝗰𝘁 𝗻𝗼𝘄

Show tool name, parsed input, and what will happen in plain English. Disable approve while a request is pending. Log who approved what. Re-validate on resume so a client cannot forge an approval for schema-valid junk input. SDK 7 documents experimental_toolApprovalSecret for in-memory agents. WorkflowAgent leans on the workflow runtime for persistence instead.

Demos optimize for magic. Production agents optimize for accountability. The boring approve button is what lets you ship tools users actually trust.
