I rebuilt a settings panel on a side Next.js app with three tabs: profile, billing, notifications. Classic `{activeTab === 'profile' && <Profile />}` pattern. Worked in dev. Then QA typed half a billing address, clicked Notifications, came back. Blank form. Support ticket filed. I "fixed" it with `display: none` on inactive tabs. State survived. So did three polling intervals hitting the same endpoint every 5 seconds.

React 19.2 shipped `<Activity>` for exactly this trap.

1️⃣ 𝗧𝗵𝗿𝗲𝗲 𝘄𝗮𝘆𝘀 𝘁𝗼 𝗵𝗶𝗱𝗲 𝗨𝗜

Conditional render unmounts the tree. Fast, simple, state gone. CSS hide keeps the DOM mounted. Scroll position and inputs survive. Effects keep running in the background. Activity sits in the middle: `mode="hidden"` applies display none, cleans up effects, defers updates, but preserves React state and DOM for instant restore.

2️⃣ 𝗪𝗵𝗮𝘁 𝗵𝗶𝗱𝗱𝗲𝗻 𝗮𝗰𝘁𝘂𝗮𝗹𝗹𝘆 𝗱𝗼𝗲𝘀

Import from `react` in 19.2 stable. Wrap each tab panel in its own Activity boundary. `mode="visible"` renders normally. `mode="hidden"` tears down effects (intervals, subscriptions, fetches), hides children, remembers state. Switch back and effects re-run with the old values still there. Hidden tabs can even pre-render at lower priority so the first paint feels instant when the user clicks.

3️⃣ 𝗪𝗵𝗲𝗻 𝗻𝗼𝘁 𝘁𝗼 𝘄𝗿𝗮𝗽 𝗲𝘃𝗲𝗿𝘆𝘁𝗵𝗶𝗻𝗴

Activity keeps subtrees in memory. Five heavy tabs with charts and grids is a memory bill. Auth flows and password fields you want destroyed on close: still use conditional render. One-off modals the user will never reopen: unmount. Activity wins on panels users bounce between: settings, wizards, multi-step editors, sidebars.

The junior fix is `display: none` everywhere. The senior fix is knowing which hide strategy matches the UX promise.
